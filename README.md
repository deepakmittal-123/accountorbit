# AccountOrbit

Source code for the AccountOrbit website: an independent accounting and tax professional referral platform for Delhi. AccountOrbit is not a Chartered Accountant firm, accounting firm, law firm, audit practice, tax authority or government service.

This repository holds the website source only. **The site has not been launched, and pushing to this repository does not deploy it.**

## Technology

- [Eleventy 3](https://www.11ty.dev/) static site, with Nunjucks templates
- Plain CSS and minimal JavaScript, with no front-end framework
- Self-hosted fonts, copied from `@fontsource-variable` packages at build time
- No analytics, trackers or third-party scripts

## Local setup

You need Node.js and npm. Then:

```bash
npm ci
npm run build     # builds the development preview into _site/
npm run serve     # builds and serves the preview locally
```

The development preview shows a banner on every page, and highlights facts that are not available yet.

## Project layout

| Path | Contents |
|---|---|
| `src/` | Pages, layouts and partials |
| `src/_data/routes.json` | Route registry: every planned URL and its status |
| `src/assets/` | CSS, JavaScript, social image and SVG favicon |
| `src/root/` | Files copied to the site root, such as `favicon.ico` and `site.webmanifest` |
| `eleventy.config.js` | Build configuration, shortcodes and technical file generation |
| `scripts/` | Production build, status, eligibility and icon scripts |
| `qa/` | Automated test suites |

`_site/`, `node_modules/` and `qa/reports/` are generated, and are not committed.

## Route structure

| Section | Path |
|---|---|
| Core pages | `/`, `/how-it-works/`, `/about-us/`, `/contact-us/`, `/request-an-accountant/` |
| Services | `/services/` and its child pages |
| Industries | `/industries/` and its child pages |
| Guides | `/guides/` and its child pages |
| Locations | `/locations/`, area-type hubs and individual area pages |
| Legal | `/privacy-policy/`, `/terms-and-conditions/`, `/disclaimer/` |

The registry lists 76 approved routes. Not all of them have pages. A link to an unbuilt route renders as plain text, and a link to a URL outside the registry stops the build.

## Technical SEO files

These are generated by `eleventy.config.js` on each build, from the route registry:

- `sitemap.xml` lists only routes that are built, QA passed, publication eligible and marked indexable. If none qualify, no file is written.
- `robots.txt` allows crawling, and references the sitemap only when one exists.
- `llms.txt` describes the site and lists eligible pages plus the core pages.
- `_headers` sets security and cache headers for hosts that read this file, such as Netlify and Cloudflare Pages.

## Indexing rules

Each route tracks these separately: owner approval, whether it is built, its QA status and its publication eligibility. Owner approval never makes a page indexable by itself.

The build stops if a page is marked indexable without meeting the rules, or while it still has an open fact. After adding or resolving facts, run:

```bash
npm run build
node scripts/set-eligibility.mjs
npm run build
```

## QA

Run a build first. The suites use a locally installed Chrome. `qa:deep` also needs the Firefox and WebKit builds used by Playwright.

```bash
npm run qa          # all pages at 8 widths: accessibility, links, metadata, form
npm run qa:home     # homepage, keyboard, reduced motion, no JavaScript
npm run qa:deep     # Firefox, WebKit, HTML validation, page similarity
npm run qa:files    # sitemap, robots, llms.txt, headers, icons, indexing rules
npm run qa:content  # content metrics report
node qa/route-audit.mjs     # status of every route over a local server
node qa/external-links.mjs  # external link check
```

To also test that specific private details never appear on the site, add them to `qa/private-terms.local.json`, which is git-ignored, as `{"terms": ["..."]}`.

## Deployment requirements

Nothing here deploys automatically. Before any deployment:

- The production build must pass: `npm run build:production`. It stops while any page still has a highlighted open fact, and this safeguard should stay on.
- The enquiry form needs a real, reviewed endpoint, set through `ENQUIRY_ENDPOINT`. Without one, the form stays disabled and says so.
- The host must serve `404.html` for missing pages, use HTTPS, and redirect to one canonical host.
- If the host does not read `_headers`, apply the same headers in its own configuration.

After deployment, check live status codes, redirects, headers and canonical URLs.
